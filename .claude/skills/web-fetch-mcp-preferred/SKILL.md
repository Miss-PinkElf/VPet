# 用 MCP fetch 代替内置 WebFetch

## 目标

把“读取网页正文”这件事固定为以下优先级：

1. 静态、公开、以文本为主的网页：优先使用 `mcp__fetch__fetch`
2. 需要 JavaScript 渲染、登录、点击、滚动、截图、表单操作的网页：改用 `agent-browser`
3. 不要请求或依赖 Claude Code 内置 `WebFetch`

这个 skill 的重点不是“所有网页都只用 fetch”，而是“把最合适的工具用在最合适的页面类型上”。

## 判定规则

### 直接用 `fetch` 的场景

符合以下任一条件，优先使用 `mcp__fetch__fetch`：

- 用户要读取某个公开 URL 的正文、摘要、标题、要点
- 页面大概率是博客、文档、新闻、帮助中心、README、论坛帖子这类文本页
- 用户要从多个公开网页中提取文字信息并汇总
- 任务目标是“拿内容”，不是“操作网页”

### 改用 `agent-browser` 的场景

符合以下任一条件，不要坚持用 `fetch`，直接切到 `agent-browser`：

- 页面依赖 JavaScript 渲染，`fetch` 返回的正文明显不完整
- 需要登录、验证码、Cookie、会话态
- 需要点击、翻页、展开折叠项、切换 tab、滚动加载
- 用户要截图、录屏、下载、打印 PDF、填写表单
- 用户明确要求“打开网页操作一下”“点进去看看”“帮我截图”

### 失败后的降级规则

如果已经尝试 `fetch`，出现以下现象，立刻判定为不适合继续用 `fetch`：

- 返回内容非常短，只有壳页面、导航或“Enable JavaScript”
- 关键正文缺失，只剩标题、页头、页脚
- 页面内容依赖交互后才出现
- 页面要求登录后才能查看

此时应说明原因，然后切换到 `agent-browser`。

## 推荐工作流

### 单页正文抓取

1. 用 `mcp__fetch__fetch` 读取 URL
2. 检查是否拿到了足够完整的正文
3. 输出摘要、结构化要点或用户要求的结果

### 多链接汇总

1. 逐个调用 `mcp__fetch__fetch` 读取公开链接
2. 对每个链接保留来源
3. 汇总时区分“原文事实”和“模型归纳”

### 动态网页

1. 先简短说明 `fetch` 不适合当前页面
2. 调用 `agent-browser`
3. 按浏览器自动化流程获取内容或完成操作

## 输出约束

- 引用网页信息时，保留原始 URL
- 如果内容是不完整抓取结果，要明确说明是推断，不要伪装成完整事实
- 如果从 `fetch` 切到 `agent-browser`，要把切换原因说清楚
- 不要把“工具偏好”暴露成无关废话，除非这会影响结果可靠性

## 工具选择示例

### 示例 1：公开博客文章

用户：
> 帮我读一下这个链接，提炼 5 个要点

做法：
- 直接使用 `mcp__fetch__fetch`

### 示例 2：需要登录的后台页面

用户：
> 登录这个后台帮我看一下订单列表

做法：
- 不用 `fetch`
- 直接切到 `agent-browser`

### 示例 3：文档站正文不完整

用户：
> 读取这个文档链接，告诉我安装步骤

做法：
- 先尝试 `mcp__fetch__fetch`
- 如果只拿到导航和壳页面，说明文档站依赖 JS
- 切到 `agent-browser`

## 环境假设

本 skill 依赖以下约定：

- 项目已通过 `.mcp.json` 配置名为 `fetch` 的 MCP server
- Claude 设置中已禁用内置 `WebFetch`
- `agent-browser` skill 可用，作为动态网页的后备方案

如果 `mcp__fetch__fetch` 当前不可用，先提示用户检查：

- 项目 MCP 是否已启用
- `uvx` 是否已安装并可执行
- Claude Code 是否重新加载了当前项目配置
