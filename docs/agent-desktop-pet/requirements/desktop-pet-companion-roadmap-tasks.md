# Tasks

## Implementation Tasks

- [x] Phase 1 / Task 1: 搭建可稳定启动的项目骨架和统一启动入口
  - Acceptance:
  - 根目录存在统一启动脚本，可启动 `frontend` 和 `backend`。
  - 前后端目录职责清晰，Python 虚拟环境初始化方式有文档或脚本。
  - 在目标环境中可完成基础安装并成功启动空壳应用。

- [x] Phase 1 / Task 2: 实现透明 Electron 主窗口和基础桌宠容器
  - Acceptance:
  - Electron 窗口支持透明、无边框、置顶显示。
  - React 应用能在透明窗口中正常渲染。
  - 主窗口关闭、重开和开发模式运行无明显异常。

- [x] Phase 1 / Task 3: 接入 Live2D 渲染链路并稳定显示模型
  - Acceptance:
  - 使用 `pixi.js@6` 与 `pixi-live2d-display@0.4.0` 成功加载 `.model3.json` 模型。
  - 模型可居中显示、缩放适配，不出现明显模糊和越界。
  - React 生命周期与 PIXI 初始化/销毁无重复渲染问题。
  - 当窗口尺寸变化时，模型可根据新尺寸重新适配，不出现明显裁切或留白。

- [ ] Phase 1 / Task 4: 完成桌宠基础交互
  - Acceptance:
  - 用户可拖拽模型移动位置。
  - 鼠标悬浮时显示最小工具栏或菜单。
  - 桌宠位置可本地持久化并在重启后恢复。

- [x] Phase 1 / Task 4.1: 补齐视觉稿要求的 hover 边框与右侧 toolbar
  - Acceptance:
  - 鼠标悬浮桌宠区域时显示高亮边框与右侧竖向 toolbar。
  - 鼠标移出后，边框与 toolbar 会短暂停留再隐藏，不会立刻闪退。
  - toolbar 布局贴近视觉稿，包含设置按钮、缩放入口和其他按钮占位态。

- [x] Phase 1 / Task 4.2: 支持窗口拖拽与右下角拖拽缩放
  - Acceptance:
  - 用户可通过顶部拖拽把手移动整个 Electron 窗口。
  - 用户可通过右下角缩放手柄调整窗口尺寸。
  - 窗口缩放时，Live2D 模型显示比例会同步调整。
  - 主进程对窗口最小宽高进行保护，避免缩到不可用状态。
  - 已修复 resize 导致的 PIXI/Live2D 生命周期报错，不再因窗口变化触发重复销毁。

- [x] Phase 1 / Task 4.3: 完成边框、模型与 toolbar 的统一联动缩放
  - Acceptance:
  - 本轮采用统一缩放基准和统一模型可视区，外框、toolbar、拖拽把手、缩放手柄会随窗口尺寸联动变化。
  - 无论尺寸变化来自右下角缩放手柄还是实际窗口 resize，渲染层都能同步最新 bounds 并触发模型与 UI 重算。
  - 主进程对窗口宽高同时提供最小值和最大值限制，避免尺寸超出可用范围。
  - Live2D 模型在保持 `PIXI.Application` 单例方案不变的前提下，进一步压缩与边框之间的留白。
  - 缩放后 UI、模型与外框视觉上表现为同一组件，而不是固定像素叠加层。
  - 本轮改动已同步更新问题清单、PRD、OpenSpec design 和 tasks。

- [x] Phase 1 / Task 5: 完成文本对话入口和气泡回复
  - Acceptance:
  - 用户可以打开输入框发送消息。
  - 前端能显示发送中、成功、失败三种状态。
  - 系统回复可同时出现在聊天面板和独立对话气泡中。
  - 对话气泡与聊天面板分离，即使聊天面板关闭也能显示，并会在数秒后自动隐藏。
  - 验证结果：已在真实开发环境完成发送测试，前端可发送消息、接收回复，并正确展示聊天面板记录与独立对话气泡。

- [x] Phase 1 / Task 6: 建立后端对话服务最小闭环
  - Acceptance:
  - Python 后端可接收前端消息并返回模型回复。
  - 前后端通信方式固定且可复用。
  - 当模型不可用时，前端可收到明确错误并提示用户。
  - 存在一个最小后端测试页，可手动向前端推送桌宠消息做联调。
  - 后端存在单独启动脚本，便于只启动 Python 服务。
  - 后端已按模块拆分为配置、API、服务、记忆抽象和 schema 层。
  - 验证结果：已在真实开发环境完成聊天联调和“后端测试页 -> 前端推送”测试，后端服务、事件流和单独启动脚本均可用。

- [ ] Phase 1 / Task 6.1: 扩展高层事件协议与最小 Pet Controller
  - Acceptance:
  - 后端事件协议至少支持 `emotion.set`、`motion.play`、`bubble.show`、`mode.switch`、`move.intent`。
  - `/dev/control` 测试页可以选择不同事件类型并发送对应 payload。
  - 前端存在最小 `Pet Controller`，统一分发后端事件，而不是把事件处理散落在多个组件中。
  - 前端至少能对五类事件做基础消费，其中 `bubble.show` 触发独立对话气泡，`emotion.set` 能驱动一次基础表情映射，其余事件至少更新到可见状态面板中。

- [ ] Phase 1 / Task 7: 落地 MVP 记忆服务
  - Acceptance:
  - 系统能从对话中抽取至少偏好、习惯、近期事件三类记忆。
  - 记忆可本地持久化并在新对话中被召回。
  - 用户至少可以清空记忆或关闭记忆写入。
