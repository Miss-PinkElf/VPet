# 桌宠毕设过程记录指南

## 1. 文档目标

这份指南用于解决两个问题：

1. 如何把桌宠项目按“毕业设计”节奏一步一步推进，而不是只做零散功能。
2. 如何在推进过程中留下可复用、可续接、可直接转化为论文材料和答辩素材的记录。

本项目建议采用：

- `context-budget-explore` 负责外层阶段推进与过程记录
- `superspec` 负责内层具体功能的规范化实施

简单理解就是：

- `explore` 管“毕设现在走到哪一阶段了”
- `superspec` 管“这一轮具体要把什么功能做完”

## 2. 推荐的记录结构

### 2.1 全局阶段记录

使用目录：

```text
.codex/explore/desktop-pet-graduation-roadmap/
```

建议长期维护以下文件：

- `workflow.md`
  - 记录毕设总目标、阶段划分、成功标准和当前阶段
- `state.md`
  - 记录当前真实进度、已确认事实、待解决问题和下一步
- `decision-log.md`
  - 记录关键决策、原因、放弃的方案和影响
- `learnings.md`
  - 记录每轮迭代的经验，方便下一轮复用
- `handoff.md`
  - 用于跨对话续接，快速恢复上下文

### 2.2 专项问题记录

当某个阶段里出现独立主题，比如：

- 前端边框联动缩放调试
- 后端简单对话联调
- 记忆系统调研

建议单独建立对应 explore 子目录，例如：

```text
.codex/explore/desktop-pet-ui-debug/
.codex/explore/desktop-pet-chat-backend/
.codex/explore/desktop-pet-memory-research/
```

这些目录只负责记录“某个主题”的实现或调试细节，不替代全局阶段记录。

## 3. 推荐的推进方式

### 阶段一：先确定当前主线

每次开始新一轮工作前，先在全局 `state.md` 里写清楚：

- 当前阶段是什么
- 这一轮的目标是什么
- 哪些内容明确不做
- 这轮完成后算成功的标准是什么

例如当前可以写成：

- 当前阶段：Phase B，前后端简单对话闭环
- 本轮目标：完成前端输入、后端简单回复、前后端联调
- 暂不做：记忆抽取、上下文感知、复杂人格状态

### 阶段二：进入 superspec 做具体功能

当目标清楚后，具体功能实现要走 OpenSpec 三件套：

- `proposal.md`
- `design.md`
- `tasks.md`

推荐做法：

1. 先在 `proposal.md` 里收敛这轮功能边界
2. 在 `design.md` 里说明模块关系、数据流和接口
3. 在 `tasks.md` 里拆成可执行、可验证的小任务
4. 实现时只围绕当前任务，不要同时扩散到其他阶段

### 阶段三：实现结束后回写 explore

每完成一轮，有产出时必须回写：

- `state.md`
  - 当前阶段是否变化
  - 本轮完成了什么
  - 还有什么问题
- `decision-log.md`
  - 这轮做了什么关键选择
  - 为什么这样选
- `learnings.md`
  - 哪些做法有效
  - 哪些做法无效
  - 下次应该避免什么

## 4. 一轮记录最少要写什么

如果你想把记录成本降到最低，至少保证每轮写下这四类信息：

### 4.1 本轮目标

- 这一轮想做成什么

### 4.2 本轮完成

- 实际做完了什么

### 4.3 本轮决策

- 为什么这样做，而不是另一种方案

### 4.4 下一步

- 下一轮最应该做什么

只要这四项持续写，后面无论是续接开发、整理周报、写论文还是做答辩 PPT，都会轻松很多。

## 5. 如何服务毕业论文写作

这套记录体系最重要的价值，不只是续接开发，还能直接转成论文素材。

### 5.1 论文里的“需求分析”

可以直接来自：

- `原始PRD.md`
- `1.md`
- `桌宠项目详细PRD.md`

### 5.2 论文里的“系统设计”

可以直接来自：

- OpenSpec 的 `proposal.md`
- OpenSpec 的 `design.md`

### 5.3 论文里的“实现过程”

可以直接来自：

- `decision-log.md`
- `learnings.md`
- 各专项 explore 中的调试记录

### 5.4 论文里的“问题与优化”

推荐统一使用这个结构：

```text
问题现象 -> 根因分析 -> 解决方案 -> 验证结果
```

当前前端边框联动缩放、PIXI 生命周期问题，已经是很好的现成素材。

## 6. 推荐的阶段节奏

按毕设节奏，建议这样推进：

1. 前端展示稳定
2. 简单对话闭环
3. 基础记忆能力
4. 轻量上下文感知
5. 设置页与隐私开关
6. 演示脚本与答辩材料

每个阶段结束时都做一次 checkpoint，确认：

- 这个阶段目标是否达成
- 哪些内容可以明确算“已完成”
- 哪些内容留到下一阶段

## 8. 一句话原则

不要只记录“做了什么”，还要记录“为什么这样做、放弃了什么、下一步是什么”。

这样这份记录才能真正服务于：

- 持续开发
- 跨对话续接
- 毕业论文撰写
- 答辩讲解

## 10. 不同场景的固定工作流

### 10.1 新需求

- 先更新全局 `state.md`
- 再看 OpenSpec 三件套
- 必要时先走 Align / Propose
- 建专项 explore 目录
- 实现完成后回写全局记录和 `tasks.md`

### 10.2 修复 Bug

- 先建或进入专项 debug 目录
- 按“问题现象 -> 根因分析 -> 解决方案 -> 验证结果”记录
- 如果影响阶段完成度，再同步全局 `state.md`
- 如果暴露设计缺口，再回写 `design.md` / `tasks.md`

### 10.3 只做记录

- 只更新全局 roadmap
- 不必进入实现
- 重点补 `state.md`、`decision-log.md`、`learnings.md`、`handoff.md`

### 10.4 阶段切换

- 在全局 `state.md` 修改当前阶段
- 在 `decision-log.md` 记录为什么切换
- 在 `handoff.md` 改当前目标和下一步
- 在 `tasks.md` 标记新的主线任务

## 11. 以后你可以怎么提需求

为了让 Codex 稳定进入正确流程，建议你以后直接按下面这种句式开头：

### 做新功能

> 继续桌宠毕设，这轮做 xxx。先读 `.codex/explore/desktop-pet-graduation-roadmap` 和 OpenSpec，再用 superspec 推进。

### 修 bug

> 继续桌宠毕设，这轮修 xxx。先读全局 roadmap，再建专项 debug 目录处理。

### 只更新记录

> 继续桌宠毕设，这轮不开发，帮我更新阶段状态、任务进度和 handoff。

### 整理论文/答辩材料

> 基于 `.codex/explore/desktop-pet-graduation-roadmap` 和 OpenSpec，帮我整理当前阶段的论文/答辩材料。
